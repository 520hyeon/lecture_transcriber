# 전사본 교정: $ARGUMENTS

작업 폴더는 `jobs/<작업이름>/`이다. 폴더가 없으면 `jobs/` 안의 작업 목록을 보여 주고 멈춘다.
한 번에 작업 하나만 교정한다 (여러 작업을 이어서 교정하지 않는다). 이 대화에 이미 다른 작업의 교정 내용이 길게 쌓여 있으면,
교정은 진행하되 끝난 뒤 요약에 "다음 작업은 새 대화에서 실행하면 Pro 사용량이 줄어든다"고 한 줄 덧붙인다.

## 공통 규칙 (반드시 지킬 것)
- 채팅창에 전사 내용을 길게 출력하지 말 것. 결과는 파일로만 쓰고, 마지막에 2~3줄 요약만 말한다.
- **교정된 전체 텍스트를 다시 쓰지 않는다.** 바뀐 세그먼트만 `edits.json`에 쓴다. 최종 md는 `apply_edits.py`가 조립한다.
- 원본 PDF·PPTX·PNG를 열지 않는다. 강의자료 정보는 `context.md`와, 필요할 때만 `data/<과목>/decks/<파일명>.json`을 읽는다.
- 들리지 않은 부분을 지어내지 말 것. 추정은 `inaudible[].guess`에만 쓴다.
- `segments.jsonl`, `whisper_raw.jsonl`, `restore.json`, `manual.json`, `job.json`, `context.md`, `transcript.txt`, `data/` 아래 파일, 강의 폴더는 직접 수정하지 않는다.
  쓰는 파일은 `jobs/<작업이름>/edits.json`(또는 `edits.partNN.json`)뿐이다.
- 파이썬은 `.venv/Scripts/python.exe`로 실행한다 (프로젝트 루트 기준).

## 순서

1. 이미 `edits.json`이나 `edits.part*.json`이 있으면 **다시 교정할지 사용자에게 묻고 멈춘다** (그대로 적용만 하려면 6단계만 실행).

2. `jobs/<작업이름>/context.md`를 끝까지 읽는다: 과목 규칙, 용어집(대표 표기 + 별칭), 교정 사전, 진도 위치, 후보 강의자료 페이지 인덱스,
   원서 참고(원서가 있는 과목).
   - **원서 참고**: 강의자료가 미등록이면 원서의 관련 절 의사코드·정의를 대신 넣어 두었다. 슬라이드가 등록돼 있으면 보조 자료다 (슬라이드 우선).
     용어 철자·기호(`A[p..q−1]`, `PARTITION(A, p, r)`) 확인에만 쓴다. 원서 내용을 전사본에 덧붙이지 않고,
     **원서의 장·절 번호를 교정본이나 문단 제목에 쓰지 않는다** (수업과 판이 다를 수 있음. 교수님이 말한 번호는 그대로 둔다).
     원서는 강의자료가 아니므로 `paragraphs`의 `slide`에 넣지 않는다.
   - **앞부분 녹음** (나뉜 녹음 `_02`, `_03` …에만 있음): 같은 날 강의의 바로 앞 녹음 마지막 몇 줄이다. 흐름을 잇는 참고용으로만 쓰고
     edits·paragraphs에 넣지 않는다 (번호도 이 작업과 무관). 첫 문단이 앞 내용을 이어 가면 제목·슬라이드 위치를 이어 붙인다.
     "교정 전" 표시면 Whisper 결과라 인식 오류가 있을 수 있다.

3. `jobs/<작업이름>/transcript.txt`를 읽는다. 형식은 한 줄에 한 세그먼트 `번호|MM:SS|텍스트|표시`.
   - 표시: 빈칸 = 보통, `U` = Whisper 신뢰도가 낮음, `R` = 환각·누락 의심 구간을 프로그램이 재전사해 복원한 문장,
     `M` = 재전사로도 복원하지 못한 청취 불가 줄(`[누락 MM:SS–MM:SS]`), `H` = 사용자가 직접 듣고 입력한 문장
   - 환각(프롬프트 누출, 같은 말 반복, 한국어를 영어로 번역한 출력)은 프로그램이 이미 찾아 재전사했다. 남은 환각만 지운다.
   - **250줄이 넘으면 200줄씩 나눠 읽고**(Read의 offset/limit), 구간마다 `edits.part01.json`, `edits.part02.json` …으로 따로 쓴다.
     각 파트는 아래 형식을 그대로 따르고 그 구간의 내용만 담는다. 문단은 구간 경계에서 끊는다 (다음 파트에서 같은 주제가 이어지면 제목 끝에 "(계속)").
   - 250줄 이하면 `edits.json` 하나로 쓴다.

4. 교정 규칙
   - 고치는 것: 잘못 인식된 단어, 용어 표기(과목 규칙·용어집 대표 표기), 띄어쓰기, 맞춤법. 교정 사전의 패턴도 적용한다.
   - 하지 않는 것: 요약, 내용 추가, 문장 창작, 말투 다듬기, 세그먼트 합치기·나누기·내용 옮기기. 교수님 말의 내용과 순서를 그대로 유지한다.
   - **시험·과제·퀴즈·제출·점수·출석 관련 언급은 절대 빠뜨리거나 바꾸지 않는다.**
   - `prefer_english_terms` 과목: 교수님이 영어로 말했는데 한글 발음으로 적힌 용어만 영어로 (포토신세시스 → photosynthesis, 마이토콘드리아 → mitochondria).
     한국어 용어로 말한 것은 바른 한국어 표기로만 고치고 영어로 번역하지 않는다 (광학성 → 광합성, 최대값 → 최댓값).
     어느 쪽인지 애매하면 Whisper가 적은 발음에 가까운 쪽을 따른다.
     수식을 읽은 경우는 수식 표기로 (x 제곱 → x², 루트 x → √x, n 분의 1 → 1/n).
     수식이 아니라 일반 낱말로 쓴 경우는 낱말 그대로.
     한국어 과목: 슬라이드 표기. 코드 과목(`keep_code_identifiers`)은 식별자를 코드 표기 그대로 (임포트 → import, 겟네임 → getName()).
     손필기 과목: 말로 한 수식은 표기 규칙대로 (x 제곱 → x²).
   - `U` 문장은 문맥과 강의자료로 확실할 때만 고친다. 확실하지 않으면 그대로 둔다. `R` 문장은 보통 문장처럼 교정한다.
   - `M`·`H` 줄은 고치지 않는다 (edits에 넣지 않음). 문단에는 포함시킨다. M 구간 내용을 추정할 수 있으면 `inaudible`에 같은 시각으로 `guess`만 적는다.
   - 강의와 무관한 Whisper 환각(예: "시청해주셔서 감사합니다", "구독과 좋아요", 같은 말 반복)만 `"text": ""`와 `"reason": "환각"`으로 지운다.

   **중요 구간과 확인 목록** — 사용자는 확인 목록에 오른 곳만 직접 듣고 고친다. 목표는 완벽이 아니라 "강의 전체를 알아들을 수 있고, 시험·강조 부분은 정확하게"이다.
   - `important`: 교수님이 시험·퀴즈·과제를 언급하거나 "중요하다 / 꼭 알아야 한다 / 시험에 나온다"고 강조한 구간.
     `kind`는 `exam`(시험) · `quiz`(퀴즈) · `assignment`(과제) · `emphasis`(강조), `summary`는 무엇이 중요한지 한 줄 (나중에 시험 관련 내용을 찾을 때 쓴다).
     강조한 말 한 문장만이 아니라 그 강조가 가리키는 설명 전체를 범위로 잡는다. 형식적인 말버릇("중요한 건 아니고")은 넣지 않는다.
   - `review`: 사람이 들어 봐야 하는 문장. **중요 구간 안**의 인식 실패(`recognition`)·불확실(`uncertain`)·청취 불가(`inaudible`) 문장,
     그리고 **강의 전체**에서 문맥과 모순되는 문장(`contradiction`).
     - 모순 문장: 발음이 비슷한 낱말 때문에 뜻이 뒤집힌 것으로 보이는 곳 (예: 앞에서 증가한다고 하다가 바로 감소한다고 적힌 문장).
       **추측해서 고치지 말고** 원문 그대로 두고 `candidates`에 후보(`["증가", "감소"]`, 원문에 적힌 쪽을 먼저)와 `why`를 적는다.
     - 중요 구간 밖의 인식 실패는 review에 넣지 않는다 (`comprehension.weak_ranges`로 처리 메모에만 남는다).
     - 중요 구간 안의 M 줄, `inaudible` 구간, 교정하지 않은 U 문장은 프로그램이 자동으로 확인 목록에 넣으므로 review에 따로 적지 않아도 된다.
   - 확인 목록이 비면 이 작업은 바로 "완료"가 된다. 정말 들어 봐야 하는 곳만 올린다 (보통 0~10곳).

5. `edits.json` 형식
   ```json
   {
     "edits": [{"i": 152, "text": "고친 문장 전체", "reason": "포토신세시스→photosynthesis"}],
     "paragraphs": [{"from": 40, "to": 58, "heading": "광합성 개요",
                     "slide": {"file": "Lecture07.pdf", "pages": "3-5", "confidence": 0.8, "at": {"40": 3, "47": 4, "52": 5}}}],
     "inaudible": [{"start": "12:30", "end": "12:45", "guess": "추정 내용(있을 때만)"}],
     "suggestions": {"terms": ["새 용어", {"term": "대표 표기", "aliases": ["다른 표기"]}],
                     "fix_rules": [{"wrong": "포토신세시스", "right": "photosynthesis", "evidence": "2, 15, 88"}],
                     "progress": {"deck": "Lecture07.pdf", "page_to": 18},
                     "notation": [{"spoken": "루트 x", "written": "√x"}]},
     "comprehension": {"score": 85, "weak_ranges": [{"from": 300, "to": 340, "kind": "recognition", "why": "잡음이 많아 엉뚱한 단어가 많음"},
                                                    {"from": 410, "to": 425, "kind": "board", "why": "점화식을 칠판에 풀며 지시어로 설명"}],
                       "need_notebooklm": false, "reason": "한 줄 이유"},
     "important": [{"from": 300, "to": 318, "kind": "exam", "summary": "핵심 공식 유도가 기말에 나옴", "why": "\"이거 시험에 나옵니다\" (305)"}],
     "review": [{"i": 88, "kind": "contradiction", "candidates": ["증가", "감소"], "why": "앞 문장과 뜻이 반대"},
                {"i": 310, "kind": "recognition", "why": "시험 범위를 말하는 부분인데 장 번호가 엉뚱함"}]
   }
   ```
   제안(`suggestions`)에는 **자동 승인 판단**을 함께 적는다: `terms`·`fix_rules`·`notation` 항목마다 `"auto": true/false`와 `"why"`(짧게).
   ```json
   "fix_rules": [{"wrong": "포토신세시스", "right": "photosynthesis", "evidence": "2, 15, 88", "auto": true, "why": "실제 낱말이 아닌 오인식"},
                 {"wrong": "증가", "right": "감소", "evidence": "88", "auto": false, "why": "둘 다 실제 낱말"}],
   "terms": [{"term": "bijection", "aliases": ["바이젝션"], "evidence": "40, 52", "auto": true, "why": "슬라이드 용어를 교수님이 반복"}]
   ```
   - `edits`: **바뀐 세그먼트만.** `i`는 transcript.txt의 번호, `text`는 고친 문장 전체, `reason`은 짧게 (`틀린→바른`).
   - `paragraphs`: 같은 슬라이드·같은 주제를 설명하는 연속 발화를 한 문단으로. **모든 세그먼트가 정확히 한 문단에 속해야 한다** (빠짐·겹침 없이, 번호순).
     - `heading`: 짧은 주제 제목 (과목 표기 규칙을 따름).
     - `slide`: context.md의 후보 강의자료에서 찾은 위치. `file`은 등록된 파일명 그대로, `pages`는 `"3"` 또는 `"3-5"`, `confidence`는 0~1.
       `at`(선택)은 문단 안에서 페이지가 바뀌는 세그먼트 번호 → 페이지. **확실하지 않거나 강의자료 미등록이면 `"slide": null`.**
       손필기 과목은 PDF 페이지를 같은 방식으로 적는다.
   - `inaudible`: `M` 줄 말고도 문장이 중간에 끊겨 내용을 알 수 없는 구간이 있을 때만 (M 줄은 프로그램이 이미 청취 불가로 표시한다). `guess`는 근거가 있을 때만.
     **구간 안에 (문장 가운데가) 드는 세그먼트는 md에서 빠진다.** 남겨야 할 문장의 시작 시각을 `start`로 쓰지 말고, 들리지 않는 부분만 감싼다.
     apply_edits.py가 빠지는 문장을 경고로 알려 주므로 의도와 다르면 고쳐서 다시 실행한다.
   - `suggestions`: 용어집에 없는 새 전문용어(한국어 과목은 교수님이 따로 말한 영어 용어 포함, `evidence`는 나온 세그먼트 번호),
     Whisper가 2번 이상 같은 식으로 틀린 패턴(`evidence`는 세그먼트 번호), 이번 강의가 끝난 강의자료 위치(`progress`), 새 표기 규칙(`notation`).
     2글자 이하이거나 흔한 일반 단어로 된 교정 규칙은 넣지 않는다.
     - `auto: true`는 **틀린 쪽이 실제 낱말이 아니고(포토신세시스처럼 사전에 없는 낱말) 바른 쪽이 용어집 대표 표기**인 교정 규칙, 강의자료에도 있거나 2번 이상 나온 용어에만.
       양쪽 다 실제 낱말인 규칙(정의 → 정리), 한국어 용어를 영어로 바꾸는 규칙, 한 번만 나온 애매한 용어, 표기 규칙은 `auto: false`.
       (한국어 → 한국어 규칙은 프로그램이 틀린 쪽을 형태소 분석기 사전으로 검사해, 사전에 있는 낱말이면 `auto: true`여도 사람 확인으로 돌린다.)
     - 프로그램(`tools/auto.py`)이 같은 기준으로 한 번 더 검사해 통과한 것만 자동 승인한다 (변경 기록에 남고 되돌릴 수 있음). 나머지는 사람 확인.
   - `comprehension`: 이 전사본으로 강의 내용을 얼마나 이해할 수 있는지 0~100. 핵심 설명이 알아듣기 어려운 구간은 `weak_ranges`에 원인(`kind`)과 함께 적는다.
     - `"kind": "recognition"` — **인식 실패가 원인**: 환각 흔적, 한국어를 영어로 번역한 출력, 앞뒤와 안 맞는 엉뚱한 단어가 많음, 청취 불가(M·inaudible)가 남음.
       다른 전사(NotebookLM)와 대조하면 나아질 수 있는 구간이다.
     - `"kind": "board"` — **교수님 말 자체가 조각남**: 칠판·화면에 쓰거나 가리키면서 "이거, 여기, 이렇게, 로그 2랑…"처럼 지시어로 설명하는 부분.
       Whisper는 들린 대로 적었으므로 대조해도 나아지지 않는다. 처리 메모에 "판서 설명(말 자체가 조각남)"으로 표시된다 (`why`에는 무엇을 설명하는 부분인지만).
     - `need_notebooklm: true`는 **중요한 설명에 `recognition` 구간이 있을 때만**. `board` 구간만 있으면 점수가 낮아도 `false`.
       애매하면 엉뚱한 단어(발음은 비슷한데 문맥에 안 맞는 말)가 섞였는지 본다: 섞였으면 recognition, 말은 제대로인데 지시어만 많으면 board.

6. 검증·조립:
   ```
   .venv/Scripts/python.exe tools/apply_edits.py <작업이름>
   ```
   - 오류가 나오면 해당 edits 파일을 고쳐서 다시 실행한다 (문단 누락·겹침, 없는 번호, 등록되지 않은 강의자료, 쪽 범위 등).
   - "같은 이름의 md가 이미 있습니다"로 멈추면 그 경로를 사용자에게 보여 주고 **덮어써도 되는지 물은 뒤 멈춘다.** 허락하면 `--overwrite`를 붙여 다시 실행한다.
   - 경고 "모순 의심 문장의 후보 낱말을 교정으로 바꿨습니다"가 나오면 그 교정을 edits에서 빼고 다시 실행한다 (확인 목록에서 사용자가 고른다).

7. 2~3줄로 요약한다 (한국어로): 교정 문장 수, 문단·슬라이드 위치 수, 중요 구간 수, 확인 목록 수(없으면 "완료"),
   제안 자동 승인·사람 확인 수, 이해도와 NotebookLM 대조 필요 여부, 저장한 md 경로.
