# 강의자료 등록: $ARGUMENTS

인자는 `<과목> <파일명>`이다. 과목은 `data/subjects.json`에 있는 과목 중 하나.
- **기본은 지정한 파일 하나만 처리한다.**
- 파일명이 없으면 2단계의 목록을 보여 주고 어떤 파일을 처리할지 물은 뒤 멈춘다. 마음대로 전부 처리하지 않는다.
- 사용자가 `--all` 또는 "전부"라고 명시했을 때만 여러 파일을 처리한다. 이때도 파일마다 3단계(예상치 확인)를 거친다.

## 공통 규칙 (반드시 지킬 것)
- 채팅창에 추출 텍스트나 인덱스 내용을 길게 출력하지 말 것. 결과는 파일로만 쓰고, 마지막에 2~3줄 요약만 말한다.
- 원본 PDF·PPTX를 직접 열지 말 것. 반드시 `pdf_pages.py`가 만든 `pages.md` / `text.md` / PNG만 읽는다.
- 자료에 없는 내용을 지어내지 말 것. 보이지 않거나 읽을 수 없는 부분은 비워 두고, 추정은 `"note"` 필드에만 쓴다.
- 강의 폴더에는 아무것도 쓰지 않는다. 이 명령이 쓰는 곳은 `data/<과목>/decks/`, `data/<과목>/refs/` 뿐이다.
- `glossary.json`, `fix.json`, `progress.json`, `suggestions.json`은 직접 수정하지 않는다. 새 용어 제안은 `check_deck.py`가 자동으로 추가한다.
- 파이썬은 항상 `.venv/Scripts/python.exe`로 실행한다 (프로젝트 루트 기준).
- 출처는 교수님 자료(슬라이드, 과제, 퀴즈, 실습 노트북)만 쓴다. 사용자가 만든 정리 노트·요약·필기는 목록에 나와도 처리하지 않고 알려 준다 (손필기 과목(`handwritten`)의 필기는 예외로 사용).

## OCR 텍스트 다루기
`pages.md`에서 `[그림 속 글자 · OCR, 잡음 있음]` 아래의 텍스트는 그림을 OCR한 결과라 오류가 섞여 있다.
- 명백한 OCR 오류는 문맥으로 바로잡아 이해한다 (예: 광합셩 → 광합성).
- `terms` / `figure_terms`에는 바로잡은 표기로 넣는다.
- OCR에서만 나오고 슬라이드 텍스트나 문맥으로 확인되지 않는 단어는 `terms`에 넣지 않는다. 남겨 두고 싶으면 `unsure_terms`에만 넣는다 (용어 제안에서 제외됨).
- 페이지의 텍스트 출처(PDF 텍스트 / OCR / 이미지 확인)는 `check_deck.py`가 `text_source`로 자동 기록하므로 직접 쓰지 않는다.

## 순서

1. `data/subjects.json`에서 해당 과목 항목을 읽고 규칙(용어 표기 언어, 표기 규칙, 코드 식별자 유지 여부)을 확인한다.

2. 대상 확인:
   ```
   .venv/Scripts/python.exe tools/pdf_pages.py --list <과목>
   ```
   - 종류는 `[슬라이드]`, `[손필기]`, `[참고 자료]` 세 가지다.
   - 지정한 파일이 목록에 없거나 이미 `등록됨`이면 그 사실을 알리고 멈춘다. 다시 등록하려면 사용자 확인이 필요하다.

3. **추출과 예상치 확인 (Claude 사용량 없음)**:
   ```
   .venv/Scripts/python.exe tools/pdf_pages.py "<파일명>" --subject <과목>
   ```
   - PDF 텍스트 추출, 그림 영역 OCR, 이미지 확인 페이지 PNG 생성을 로컬에서 한다. 처음에는 덱 하나에 1~2분, 다시 실행하면 캐시로 몇 초다.
   - 출력의 `예상: 텍스트 n쪽 / OCR n쪽 / 이미지 확인 n쪽`과 이미지 확인 페이지 번호를 사용자에게 그대로 보여 준다.
   - **"진행할까요?"라고 묻고 멈춘다.** 사용자가 진행하라고 하기 전에는 `pages.md`나 PNG를 읽지 않는다.
   - 참고 자료는 텍스트 글자 수만 보여 주고 같은 방식으로 확인받는다.

4. **슬라이드·손필기** → `data/<과목>/decks/<파일명>.json` 작성
   - `pages.md`를 읽는다. `[출처: 이미지 확인 …]` 페이지만 같은 폴더의 PNG를 Read로 직접 본다.
     손필기는 모든 페이지가 이미지 확인이다. 페이지가 많으면 10~20쪽씩 나눠 읽고 JSON에 이어서 쓴다.
   - 형식 (모든 페이지가 정확히 한 번씩 있어야 함):
     ```json
     {
       "file": "<파일명>",
       "title": "덱 전체 제목 (예: Chapter 3. 강의 제목)",
       "pages": [
         {"page": 1, "title": "페이지 제목", "summary": "이 페이지가 설명하는 내용 1~2문장",
          "terms": ["페이지에 나온 전문용어"], "figure_terms": ["그림 속 라벨, 그림을 설명할 때 쓰일 용어"],
          "code_names": ["예제 코드의 함수·변수 이름 (선택)"],
          "unsure_terms": ["OCR에만 나와 확인 안 된 단어 (선택)"]}
       ]
     }
     ```
   - `title`: 슬라이드에 적힌 제목을 그대로. 제목이 없으면 내용을 보고 짧게 붙인다.
   - `summary`: 200자 이내. 나중에 전사본의 문단을 슬라이드에 맞출 때 쓰므로, 무엇을 설명하는 페이지인지가 드러나게 쓴다.
     표지·목차·"Any questions?" 같은 페이지도 빠뜨리지 말고 짧게 적는다.
   - `terms` / `figure_terms`: 과목 규칙에 맞는 표기로 쓴다.
     - `prefer_english_terms` 과목: 영어 용어 그대로 (예: photosynthesis, enzyme).
     - 한국어 과목: 슬라이드 표기 그대로. 한국어면 한국어로, 괄호 안 영어가 있으면 `"광합성(photosynthesis)"`처럼 함께 쓴다.
     - 코드 과목: 키워드·API 이름은 코드 표기 그대로 (`import`, `return`, `getName()`). 예제에만 나오는 변수 이름(tmp, a1 등)은 `terms`가 아니라 `code_names`에 넣는다.
     - 손필기 과목: 필기에 나온 개념 용어(한국어와 영어가 병기된 것은 둘 다), 수식은 `subjects.json`의 표기 규칙을 따른다.
   - `figure_terms`에는 그림에 실제로 보이는 라벨이나 그림이 직접 나타내는 개념만 넣는다 (예: 세포 그림 → nucleus, membrane). 상상해서 넣지 않는다.
   - `terms`에는 **명사형 전문용어만** 넣는다. 문장·구절("광합성의 효과", "에너지를 저장함"), 숫자·주소, 캡션은 넣지 않는다.
     너무 일반적인 단어(개념, 내용, 예제 등)는 넣어도 `subjects.json`의 `term_stopwords`로 걸러진다.
   - 용어 제안 규칙 (`check_deck.py`가 `tools/terms.py`로 자동 처리):
     - `figure_terms`는 인덱스에만 쓰이고 제안에는 영어·코드 표기의 짧은 용어(cell, getName())만 들어간다.
     - `"광합성(photosynthesis)"`처럼 괄호로 병기하면 대표 표기 + 별칭으로 묶인다. 한영 짝은 꼭 이 형태로 적는다.
     - 여러 페이지에 나오거나 페이지 제목에 나온 용어는 등록할 때 자동 승인되어 바로 용어집에 들어간다 (변경 기록에 남고 되돌릴 수 있음).
       한 페이지에만 나온 애매한 용어는 과목 관리 화면 "확인이 필요한 제안"에 남는다.

5. **참고 자료** (교수님 실습 노트북 ipynb, 과제 docx) → `data/<과목>/refs/<파일명>.json` 작성
   - `text.md`를 읽는다 (길면 나눠 읽기). 이미지 분석은 하지 않는다.
   - 형식: `{"file": "<파일명>", "summary": "자료 내용 2~3문장", "terms": ["용어", ...]}`
   - 노트북은 과목 용어와 함께 코드에 나오는 주요 함수·라이브러리 이름을 `terms`에 넣는다.

6. 검사·등록:
   ```
   .venv/Scripts/python.exe tools/check_deck.py <과목> "<파일명>"
   ```
   오류가 나오면 JSON을 고쳐서 다시 실행한다. 통과하면 원본 정보와 페이지별 텍스트 출처가 기록되고, 새 용어가 `suggestions.json`에 추가된 뒤 자동 승인 분류된다.
   같은 파일을 다시 등록하면 그 파일에서 나온 대기 중 용어 제안은 지우고 새로 계산한다.

7. 2~3줄로 요약한다: 등록한 파일, 실제로 본 이미지 수, 새 용어 제안 수, 읽지 못한 페이지 등 문제가 있으면 그 내용.
